# 软件交付流程

1. 先读取项目文件与任务验收条件，复用已有约定。没有证据时不要猜测文件内容。
2. 说明需要修改的文件，保持变更与任务范围一致。
3. 修改在任务工作副本完成，最终由用户检查差异后合入项目。
4. 使用已有测试或针对行为编写测试。命令执行必须遵守应用的确认机制。
5. 页面任务应检查可访问性、正常状态、错误状态和小屏显示；需要时使用 browser_check。
6. 不删除或放宽失败测试来制造通过。不声称未经执行的测试通过。
7. 最后交接：实现内容、实际验证、变更文件、遗留问题、下一位成员需要知道的事项。

## 工具边界

技能提供工作方法，不授予额外权限。脚本、MCP 和插件仍经过应用工具执行层。
终端运行在本机；工作副本仅隔离项目文件，不能替代操作系统沙箱。
