# 05 · 文档分段与 BM25 检索

代码入口：`retrieval.py`。原来的 `knowledge.py` 保留为 M0 对照基线，完整应用使用 Retriever。

## 为什么先过滤权限

`Store.documents(user)` 先选同一租户，再检查允许角色。只有这些资料参与分段、排序和返回。隐藏文档也不会贡献本次排序统计，避免把无权内容放进模型上下文后再尝试删除。

## 分段与来源

每段最多 600 个字符，相邻段重叠 80 个字符。重叠降低边界把一句话切断的影响，但会增加重复内容。当前采用字符窗口，简单且可复现；复杂文档可以改成按标题、段落和句子分段。

段 ID 包含资料 ID、版本和起始偏移：

```text
IT-001:v1:0
```

这样可以知道引用来自哪份资料的哪个版本。历史回答保存引用快照，更新资料后不会把历史引用悄悄换成新内容。

## 分词与 BM25

英文提取单词，中文提取相邻两个汉字的片段。先做 Unicode 归一化和英文大小写统一。中文双字切分不是真正的语言理解，但无需下载分词模型，便于观察行为。

BM25 综合词频、文档频率和长度归一化。一个词在当前资料集中越常见，它用于区分相关文档的作用通常越弱；同一个词在一段内重复很多次，收益会逐渐饱和。

实现中 k1=1.5、b=0.75，标题重复计入以提高标题词权重。计算每个查询词的 IDF 和长度归一化分数，最后排序取最多四段。少量词面重合还要通过标题或覆盖率条件，减少偶然匹配。

## 本项目的检索边界

当前是词法 RAG 检索，不含预训练语义 embedding，也不依赖向量数据库。它可能无法把“远程办公连不上”自动对应“VPN 连接失败”。真实 Agent 可以先改写查询，但仍需评测验证。

如果要增加语义检索，应建立 embedding 适配器、分段索引与权限元数据，再把 BM25 与向量结果融合，最后考虑 rerank。使用同一标注集比较 Recall@k、质量、延迟和费用，不要仅凭技术名词判断改进。

## 实验

管理员导入“打印机排障”资料，提问“打印机无法打印”。观察版本号和引用。再把分段大小改为 300，检查长资料的召回与重复片段变化。

检索指标 Recall@k 表示前 k 个结果中找到了多少应找到的相关资料。是否充分回答问题还需要下一步生成和依据评测，不能用召回率代替业务完成率。
