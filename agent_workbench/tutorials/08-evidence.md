# 08 · 引用、充分性与拒答

代码入口：`FinalArguments`、`AgentService._run()` 的 finish_answer 分支与 REVIEW_PROMPT。

## 三层验证

第一层是来源存在：chunk_id 是否属于本次可访问检索，引用文字是否逐字出现在该片段。应用使用内存中的命中快照校验，模型不能凭空填写资料 ID。

第二层是语义支持：引文是否支持具体结论。原文提到“VPN 连接”，无法支持“VPN 月费是 30 元”。这个问题需要语义审核和人工标注；字符串包含检查无法解决。

第三层是回答充分性：结论是否回答了用户真正的问题，是否遗漏条件、版本或例外。引用正确的片段，也可能只回答了问题的一半。

## 状态代表什么

| 状态 | 含义 |
| --- | --- |
| answered | 真实模式的候选实质回答，必须附有来源；仍应核对质量 |
| evidence_found | 展示匹配原文，常用于规则演示，不保证问题已解决 |
| insufficient_evidence | 当前依据不足以给出结论 |
| needs_clarification | 用户需补充具体信息 |
| awaiting_confirmation | 已准备工单草稿，等待用户确认 |
| failed | 运行在协议、工具、预算或系统边界失败 |

拒答不等于程序异常。资料没有答案时选择不足，通常比编造事实更符合业务要求。失败状态则应提供可定位的错误码。

## 数据内容中的指令

知识文档可能包含“忽略系统规则”之类文本。应用把资料放在工具返回数据中，提示模型不要执行资料指令，并让审核者检查回答。更可靠的边界仍然是工具白名单、用户权限和确认机制。

这些措施不能保证消除全部提示注入。需要在评测中加入恶意文档、错误来源、混合可信内容和越权请求，检查真实模型的行为。

## 引用版本与历史

保存的引用包含 document_id、version、chunk_id、title 和 quote。资料更新后，历史回答保留原快照，方便说明当时依据。历史消息本身也属于敏感数据，需要明确保留期限和访问规则。

## 实验

比较“VPN 如何排障”和“VPN 月费”。前者资料有步骤，后者资料没有金额。再查看 `test_forged_citation_is_never_published`，理解模型连续返回假 ID 时为什么最终失败。

如果要改进依据质量，应建立“问题—期望关键事实—相关原文—不可推断内容”的标注，而非只记录答案字符串是否相等。
