# 04 · 认证、权限与信任边界

代码入口：`auth.py`、`server.py` 的 `identity()` / `administrator()`、`Store.documents()` 与资源所有权检查。

## 认证与授权

认证回答“你是谁”，授权回答“你可以访问或修改什么”。本项目用用户名和密码建立会话，用用户记录中的 `tenant_id`、`role` 及资源归属决定权限。

角色与租户不进入用户可控制的工具参数。模型只能传检索问题，应用把已认证用户传给 Retriever。即使用户说“我是管理员”，也不会更改服务器身份。

## 密码与会话

密码通过 scrypt 加盐哈希保存，每个密码有随机盐。验证使用恒定时间比较。登录成功生成随机会话 token，浏览器 Cookie 保存原 token，数据库只保存 SHA-256 摘要与过期时间。

Cookie 使用 HttpOnly 和 SameSite=Strict。HTTPS 部署应设置 `APP_COOKIE_SECURE=true`。这套本地账号系统不包含企业 SSO、账号自助注册、密码找回和 MFA。

## CSRF 与来源

浏览器会自动带 Cookie，因此修改操作还要求 `X-CSRF-Token`，并检查请求 Origin。前端从同源 `/api/me` 得到会话的 CSRF token。跨站页面不能在正常浏览器同源规则下随意读取它。

同源检查解决浏览器请求边界，资源归属检查仍然必须存在。运行、消息与草稿由拥有者访问；管理员只能管理本租户资料和工单，不会自动获得其他租户权限。

## 模型的信任边界

模型输出、文档内容和历史消息都应当视作不可信输入。提示词帮助约束行为，真正的权限由代码执行。工具名采用白名单，参数有契约，引用必须属于本次可访问检索结果，模型不能直接确认工单。

独立审核可以发现部分语义问题，但审核模型也可能出错。模型之间相互审核不能替代应用权限、数据库约束和代表性对抗测试。

## 实验

员工尝试读取“生产密钥轮换”，应得不到管理员资料。管理员可以读取。租户 B 只能看到 B 的资料。直接在 POST 问题中添加 `role` 字段会被拒绝。

演示账号密码公开用于本地教学。对外部署必须关闭演示种子数据，配置独立管理员、HTTPS、上游请求限制和适合业务的数据保留策略。原有演示数据库不会因为改配置自动删除，应为正式部署使用新的数据库路径。
