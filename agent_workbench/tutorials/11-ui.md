# 11 · 前端状态、DOM 与交互

代码入口：`web/index.html` 定义页面结构，`style.css` 定义视觉与响应式布局，`app.js` 处理状态和 API。没有前端打包器，服务直接托管这三个资源。

## 页面状态

state 保存当前身份、会话、是否忙碌、工单意图、事件连接、章节和草稿状态。数据库仍是事实来源：刷新后先请求身份、历史和工单，再恢复展示。

不要把界面禁用按钮当作权限验证。按钮帮助用户避免误操作，服务器还必须检查 CSRF、资源归属和业务状态。

## 从提交到结果

`submitQuestion()` 在没有会话时先创建会话，显示用户消息，再提交运行请求。`watchRun()` 建立 EventSource，把阶段事件变成右侧时间线。收到 done 后读取最终运行结果，显示消息、引用、审核和用量。

新建会话会关闭当前页面的事件连接，但不会取消服务器任务。旧任务仍可从历史查看。当前产品没有取消运行接口，耗时由服务端预算限制。

## 处理模型内容

模型文字、资料和工单描述都通过 `textContent` 或 DOM 文本节点插入，不作为任意 HTML 执行。引用用 details/summary 展开。学习中心的 Markdown 使用受限渲染器，只创建固定标签，不执行文档中的 HTML 或脚本。

这也是为什么不要直接把模型输出赋给 innerHTML。若后续加入富文本，需要成熟的解析与清洗策略，并配合 CSP 和 XSS 测试。

## 交互与反馈

登录、导入、确认都显示错误反馈。运行期间禁用发送，避免同一会话同时处理多个请求。工单确认立即禁用按钮，服务器幂等继续保护重复请求。事件多次连接失败后提示刷新恢复。

移动端收起侧边历史和运行面板，保留主要问答与导航。较窄屏幕可以通过每条回答的运行结果查看数据；完整时间线适合桌面展示。

## 修改界面的方法

颜色首先调整 CSS 根变量。修改功能时先找 API 数据形状，再找对应 render 函数。知识卡片在 refreshKnowledge，工单在 refreshTickets / renderDraft，教程在 loadChapter。

练习：新增“查看引用数量”提示，只读取 result.citations.length；然后设计一个无引用结果，确认不会显示 undefined。验证正常、空状态、错误状态和小屏幕，不能只看一张成功截图。
