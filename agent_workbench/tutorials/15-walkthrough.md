# 15 · 完整代码走读与练习答案

这一章把实现按一条真实请求串起来。可以在编辑器中跟着跳转，每次只读相关函数。

## 路径 A：有依据的回答

1. 浏览器 app.js 的 submitQuestion 创建会话并 POST runs。
2. server.py 的 identity 从 Cookie 找到会话，检查 CSRF；路由检查会话拥有者。
3. storage.py 的 create_run 保存 queued 与用户消息，唯一索引防止同一会话并发。
4. BackgroundTasks 调用 AgentService.execute，把状态改为 running。
5. _run 组装有限历史、系统规则和当前请求；invoke 检查预算并调用 Provider。
6. 模型请求 search_knowledge，SearchArguments 校验查询。
7. Retriever 取得有权资料，分段，计算 BM25，返回带版本的片段。
8. 工具结果返回给模型；模型调用 finish_answer。
9. FinalArguments 校验结构，应用检查 chunk_id 与逐字引用。
10. reviewer 独立审核；批准后 Store.finish_run 保存结果、助手消息和完成事件。
11. SSE 把阶段发送给 watchRun，界面读取最终结果并用文本节点展示。

## 路径 B：需要人工工单

用户选择工单意图。模型可先检索，再调用 prepare_ticket。应用检查 intent，生成本地 pending 草稿；finish_answer 返回 awaiting_confirmation。此时没有正式工单。

用户点击确认，带草稿 ID 与 CSRF token 请求 decision。应用检查拥有者与运行完成状态，在事务里创建工单、更新草稿并写审计。重复确认返回原工单。管理员可以在本租户内更新处理状态。

## 路径 C：失败

网络异常重试仍失败时，ProviderError 传到 execute，保存 failed 与错误码，并取消待确认草稿。工具参数错误可修正两次，继续错误则终止。重启残留任务由 initialize 标记中断失败。

## 练习参考答案

**为什么权限在检索前过滤？** 防止无权资料进入模型上下文，避免依赖生成后的不可靠删除。权限应同时保护文档、会话、事件与工单。

**为什么引用真实仍可能没回答问题？** 原文可能只讨论相近主题，缺少金额、条件或结论。需要检查语义支持和问题充分性。

**如何添加打印机知识？** 用管理员导入资料，设置员工和管理员角色；用员工查询，再补充相关、无答案与越权用例。先通过 API 或界面使用现有导入能力，无需修改源码数据。

**标题加权解决了什么？** 降低正文偶然出现“失败”等通用词造成的排序干扰。它不能解决全部语义检索问题，应在代表性数据上比较。

**如何让无限搜索停止？** 在循环外维护调用次数、累计 token 与截止时间，工具继续被请求也不能绕过预算。测试用假模型持续请求检索来验证。

**为什么确认要用事务和唯一约束？** 两个请求可能同时到达，界面禁用无法保护服务端。事务序列化读改写，唯一键阻止重复插入。

**增加 Agent 怎么证明收益？** 固定样本、模型和其他参数，分别运行单 Agent 与审核方案，比较任务完成率、错误拒答、延迟和费用，并报告样本限制。

## 学完后的能力检查

你应能够独立启动与配置项目，沿请求定位函数，增加一条资料和测试，解释引用失败，修改工单字段并完成数据迁移设计，说明单机部署的限制，并用失败案例证明取舍。

需要深入的后续领域包括：语义检索、异步并发、成熟编排框架、企业身份集成、分布式任务、外部工单一致性和更严谨的真实评测。这些是成品的扩展方向；本教程已覆盖当前交付中每个核心模块的机制与修改入口。
