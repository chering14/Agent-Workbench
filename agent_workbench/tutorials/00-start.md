# 00 · 运行成品与学习方法

本教程对应 Agent Workbench 1.0 的完整实现。业务是企业知识与工单协作：登录后查询资料，核对回答引用，必要时准备工单，并在确认后创建正式工单。你可以从头学习，也可以运行功能后查对应章节。

## 第一次启动

Windows 在仓库根目录双击 `启动项目.bat`，或运行：

```powershell
.\scripts\start.ps1
```

脚本会检查虚拟环境、安装锁定依赖、在缺少配置时创建 `.env`，然后在本机 8765 端口启动。已经配置的 `.env` 不会被覆盖。停止服务时在运行窗口按 Ctrl+C。

```powershell
.\.venv\Scripts\python.exe -m agent_workbench serve
```

打开 `http://127.0.0.1:8765`。默认规则演示可以离线运行，不调用模型。登录页的“员工 / 管理员 / 租户 B”按钮会填入对应演示账号，点击登录后进入工作台。

## 用十分钟理解成品

1. 员工提问“VPN 连接失败，如何排查？”，展开引用，查看运行过程。
2. 问“VPN 月费”，观察资料相关但不包含答案时的处理。
3. 选择“生成工单草稿”，发送问题，核对草稿后确认创建。
4. 到工单中心确认只有一张工单；刷新页面观察数据仍然存在。
5. 用管理员登录，导入一段 Markdown 或文本，回到协作台检索它。
6. 进入学习中心，按章节阅读代码原理。

演示模式用明确的规则产生工具请求，体验的是应用流程。真实模式才包含模型决策和模型审核。两种模式共享参数校验、权限、数据库和工单确认逻辑。

## 配置真实模型

编辑仓库根目录 `.env`，设置 `APP_MODE=live`、`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`，重启服务。接口需要支持 Chat Completions 风格的 function calling、`tool_choice=required` 和对应工具 Schema。提供商对兼容性的支持程度需要实际验证。

先保留 `APP_SEED_DEMO=true` 可在演示业务数据上验证接口。真实部署时关闭演示数据，并配置自己的管理员。密钥只放在本地环境或部署密钥管理系统中。

## 学习与验证

每章包含概念、代码入口、实验和理解检查。先预测输出，再执行，最后解释差异。遇到 Python 语法不熟悉，可以先读第 02 章。所有练习都有第 15 章的参考答案，练习不阻塞使用成品。

运行完整验证：

```powershell
.\scripts\test.ps1
```

测试检查已知约束；评测汇总固定样本的表现。它们的通过不代表真实用户任务必定成功。真实模型的效果还要在配置完成后通过业务评测建立证据。
