# 10 · Skills：把经验变成按需资料

源码入口：extensions.load_skill、Extensions.catalog、Extensions.skill；示例 team_assets/skills/software-delivery/SKILL.md。

Skill 是一个目录，入口 SKILL.md 由 YAML 元数据和 Markdown 正文组成。本项目读取 name / description，先将简短目录提供给模型，需要时通过 read_skill 读取正文或资源。这比把全部技能文本写进每次系统提示更节省上下文。

```markdown
---
name: software-delivery
description: 处理代码开发、验证和交接时使用。
---
先确认验收条件，再查看已有代码。
每次改动后运行对应检查，报告实际命令与结果。
```

在“能力中心”添加 Skill，配置 JSON 的 path 为绝对目录，启用后点击检查。技能资源必须位于该目录，不能利用 ../ 读取其他目录。正文和单次资源有大小限制；大材料拆到 references，模板放 assets，脚本放 scripts。

导入的脚本不会因为写在 Skill 中就自动执行。本版 read_skill 是读文本；需要执行技能脚本时，可将脚本明确做成声明式插件工具，或由用户安排获准的命令。不要误以为支持技能目录就代表兼容所有框架的脚本运行约定。

技能中的 allowed-tools 等元数据不能扩大成员权限，正文也不能覆盖系统执行边界。它是用户导入的专业资料，有助于模型做决策，但不是新的权限来源。

编写好技能要描述适用场景、输入、步骤、验收和失败处理。避免把一整本教程塞进正文。比如代码审查技能应说明检查修改的行为和测试证据，而不是只写“你是一位资深专家”。

本项目只实现导入、启停、元数据、按需阅读和资源路径边界；没有在线技能商店、自动安装依赖或完整规范一致性认证。标准格式来源见 docs/SOURCES.md，扩展时应继续按上游当前规范验证。

自检：Skill 与工具有什么区别？答案：Skill 主要提供做事方法和资源，工具是程序执行能力。它们能配合，但读取一段方法并不会自动授予文件或命令权限。
