# 14 · 原生 Web、SSE 与页面状态

源码入口：team_web/index.html、style.css、app.js；api.events 和 history。

页面用原生 HTML/CSS/JavaScript，避免前端构建链成为本地启动前提。左侧切换项目与功能，中间工作群，右侧任务及预算。成员和扩展通过表单管理，任务详情汇总要求、确认操作、报告、文件和差异。

state 保存当前项目、成员、任务、用量和事件。boot 读取 bootstrap；selectProject 关闭旧 EventSource，取项目状态和历史，再按最后 seq 订阅 SSE。新事件加入消息列表并触发短延迟 refresh，获取服务端当前任务状态。

SSE 是服务端向浏览器单向推送。每条事件携带 id，浏览器重连带 Last-Event-ID，服务端从后续 seq 继续读取。它不需要 WebSocket 双向通道，因为用户动作仍是普通 HTTP POST。历史来自数据库，不依赖内存缓冲。

前端用 textContent 渲染模型和工具文本，不直接把外部内容塞进 innerHTML。教程用受控的基础 Markdown 渲染器支持标题、列表、代码块，不执行 HTML。文件预览走单独 iframe，与工作台 DOM 隔离。

成员 API Key 只在密码输入框临时存在，提交后保存在系统凭据服务，关闭弹窗移除表单；页面状态不保存明文 key。项目切换后可见负责人列表依据 member_ids 过滤；成员管理页仍列出全局配置。

错误反馈必须准确：请求失败显示服务端详情；“已完成”“已合入”和“等待确认”不能混淆。对于有副作用的动作，页面先展示本次具体参数，不让一个笼统按钮授权后续所有工具。

界面验证包括空项目、计划采用、依赖执行、文件预览、合入、添加成员、扩展检查、教程和窄屏布局。自动化接口测试不能替代浏览器流程，因为事件绑定、可见性、CSS 和 iframe 行为只有页面运行后才体现。

自检：为什么切项目要关闭旧 EventSource？答案：避免旧项目事件继续写进当前页面，也减少无用连接；服务端仍会保存历史，不会因关闭订阅丢任务。
