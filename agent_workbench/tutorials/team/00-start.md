# 00 · 从完整成品开始

这门教程对应本仓库 2.0 的默认应用。你不需要先完成练习才能使用项目。先体验，再沿数据流读代码；每章的“自检”都附答案，用于确认理解。

你扮演负责人，创建项目、添加模型成员、安排任务、检查工具动作、验收成果。一个成员由模型连接、职责、工具权限和预算限制组成。模型负责选择下一步，程序负责真正执行、持久化和限制操作。

Windows 运行 scripts/start.ps1，打开 http://127.0.0.1:8765。安装脚本保留已有 .env，没有任何登录步骤。先用演示成员选择“自动规划”，采用计划，开始草稿任务；查看 demo/index.html 的预览和变更，再合入。这个流程真的写文件、保存任务和做依赖交接，但内容由固定规则生成。

配置真实模型后，同一流程由模型通过函数工具调用来读写文件。第一次验证可安排一个小任务：“创建 add.py，实现 add(a,b)，写 test_add.py，执行 python -m pytest -q，报告结果”。命令执行会暂停，等待你核对参数并允许本次操作。没有真实密钥时，不宣称供应商调用已经通过。

建议阅读顺序：01 理解产品与对象；02 补齐 Python 必要基础；03-09 理解从请求到执行；10-13 学扩展与验证；14-17 学界面、测试、运维和全流程。每章引用文件路径都相对仓库根目录，在编辑器打开即可对照完整源码。

默认数据存于 var/team：team.db 保存配置、任务、消息和账单，workspaces 保存任务副本，projects 保存界面创建的新项目。不要为了重试删除数据；界面提供停止、重试和保留文件继续。

自检：为什么离线演示可以证明交接流程可运行，却不能证明模型会写好代码？答案：它覆盖了调度、文件和数据流，但模型决策与真实供应商完全未参与。两种证据必须分开。
