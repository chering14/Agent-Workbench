# 09 · 工具执行、确认与幂等

源码入口：runtime.allowed_tools、execute、execute_tool，workspace.run_command。

工具描述让模型知道“能请求什么”，工具白名单决定“程序允许什么”。files 对应文件读取/检索/编辑，commands 对应命令，browser 对应浏览器检查，extensions 对应 Skill 和外部工具。规划任务只保留调查与 submit_plan，不写文件。

run_command、browser_check、extension_call 在执行前把名称、参数和待确认状态写入数据库，页面展示本次操作。approve/reject 只允许作用于 waiting_approval 状态。拒绝后将明确拒绝结果返回模型，不应换工具绕过。

确认过的扩展调用还检查扩展配置版本；若确认期间配置变化，要求重新提出调用。此检查针对登记的配置，不等同于对外部服务、磁盘脚本和所有依赖做不可变签名验证。

命令使用 argv 数组，shell=False；参数不会作为一整段 shell 字符串插值。python 自动使用当前虚拟环境解释器。若用户明确批准的是 powershell/bash 等解释器命令，它仍能执行该解释器提供的完整能力，所以“无 shell 拼接”不能被称为 OS 沙箱。

命令有 1-120 秒限制，输出文件超过限制会停止，返回最多 24000 字节日志，并包含 exit_code、status 和耗时。子进程环境仅保留基本系统变量，不默认继承模型密钥。任务取消会请求停止正在运行的命令；外部工具已发生的副作用不会自动撤销。

幂等意味着重复请求不会造成重复业务效果。计划采用使用事务与状态检查，文件合入识别已等于目标的文件；这些可重复检查。任意外部命令或 MCP 服务则无法由本应用保证幂等，因此重启不重放 pending，失败后需要用户明确继续。

副本只约束内置文件工具。获准的命令可用绝对路径访问主机，MCP 服务也可能有网络或远端账号权限。这正是确认框展示工具名、参数和边界说明的原因。

自检：审批一次命令后，模型下一条命令会自动获准吗？答案：不会，确认范围只覆盖当次工具调用及参数。
