# ADR 0001：先建立可验证的检索基线

此为 M0 历史决策。当前完整应用采用 [ADR 0002](0002-complete-application.md)。

- 日期：2026-10-20
- 状态：M0 已采用；真实模型和框架选择待 M1 验证
- 背景：目录为空；用户能在 AI 协助下完成项目，希望同时达到求职作品质量并理解相关知识。

## 决策

M0 使用 Python 3.11+ 标准库实现固定检索流程，数据契约、检索、工作流、评测与 CLI 分离。
先保留原文引用，建立权限过滤和回归样本。后续在相同任务上对比真实模型、不同检索与多 Agent 方案。

业务方向暂定为企业知识库与工单协作。用户尚未确认方向与模型预算，因此 M0 不依赖外部服务。

## 理由

- 每个新组件都增加解释与排查成本，先建立能看懂且可运行的闭环。
- 固定基线帮助分辨改进来自模型、检索、提示还是流程变化。
- 原文引用让来源可核对，避免把未经验证的生成能力写成事实。
- 先分离业务与入口，方便后续加入 API、模型与新的检索实现。

## 当前检索规则

英文使用单词，中文使用相邻两个汉字的片段；标题匹配权重为正文的两倍。
总分为 `(2 × 标题匹配数 + 正文匹配数) / (3 × 问题词数)`，达到 0.2 才返回，最多两篇。
阈值是透明的基线规则，尚未通过代表性数据校准，不代表语义置信度。

## 代价和限制

- 无语义理解、生成、动态工具决策和会话记忆。
- 词法匹配会漏召回、误召回，不支持生产规模资料。
- 引用校验只检查来源归属，不能检查语义支持和回答充分性。
- 租户与角色仅为本地可信上下文演示，没有认证系统。
- 内存执行记录没有持久化、错误链路和完整监控。
- 合成样本覆盖范围有限，需要后续真实或代表性脱敏样本与留出集。

## 后续评估

M1 对真实模型的工具调用、结构化输出、超时、费用与可观测性做小型验证。
当流程需要持久化、暂停恢复与明确状态图时，评估 LangGraph；当需求主要是轻量工具循环与委派时，评估 Agents SDK 或简单适配层。
正式选择时只保留一条主路线，记录版本、替代方案与测试结果。
多 Agent 是否进入主流程取决于相同任务集上的质量、延迟与成本对比。
