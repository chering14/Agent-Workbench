# ADR 0003：本地多模型软件团队

日期：2026-10-22。状态：采用。

用户将产品方向明确为本地的一人公司工作群：无需登录，自带多个模型 API，手动或自动分工，以软件成果为第一用例，支持 Skills、MCP 和插件。此前企业知识工单方向作为历史实现保留。

决策：默认 serve 切换到 team.api；使用独立 team.db 保留旧数据；原生 Web 中统一展示群事件、任务和结果。成员不是供应商品牌的别名，而是模型连接加职责、档位、权限、输出/步骤限制。项目可以选择入群成员。

调度采用有限并发任务队列，同成员串行、依赖完成后运行；不让全群每条消息自动互相回复。模型规划提交结构化计划，人工采用后生成草稿。自动路由使用用户档位与价格，不声称有未经评测的智能模型榜单。

文件使用 base/work 副本与哈希冲突检查，避免多个成员直接覆盖同一工作目录。相比 Git worktree，这可支持非 Git 文件夹且启动简单；代价是复制成本、有限规模、没有完整提交/分支语义，也不是 OS 沙箱。

选择轻量自有编排而非直接依赖 AutoGen 或 LangGraph：用户需要可读、可学、具有本机确认与副本合入语义的成品；当前状态机规模可控。代价是恢复、调度和验证由本项目维护。未来如果需要分布式、长期运行、复杂图恢复，应重新比较成熟框架和迁移成本。

MCP 使用官方 SDK，避免自写协议；插件明确使用 Workbench v1 清单，不声称兼容所有现存框架插件。Skills 是受信任用户导入的上下文资源，不授予执行权限。扩展检查与实际调用区分，命令/MCP/插件调用需要用户确认当次参数。

本地无登录不等于公网应用：默认 loopback，写操作需要每次启动生成的页面令牌，检查 Host/Origin，不实现远程团队身份。容器有显式 --container 开关，宿主端口仍绑定 loopback。

完成状态代表 Agent 提交报告，最终是否满足业务验收由工具证据和用户检查决定。模型自述的“测试通过”不能替代日志与测试用例。
